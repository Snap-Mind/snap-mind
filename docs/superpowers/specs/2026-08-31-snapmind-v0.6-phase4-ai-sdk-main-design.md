# SnapMind v0.6 Phase 4 — `@ai-sdk` + AI in main

Status: design approved, ready for planning
Owner: Louis Liu
Last updated: 2026-09-02
Parent: [`2026-08-11-snapmind-v0.6-roadmap.md`](./2026-08-11-snapmind-v0.6-roadmap.md)

## Goal

Move every model call out of the renderer. Main resolves the agent, decrypts the API key, and runs `@ai-sdk` `streamText`. The renderer is a view: it sends `{ agentId, messages }`, paints tokens, and aborts. This unblocks Phase 5 (MCP / tools need Node stdio) and removes the custom adapter layer.

## Deviation from the roadmap

1. **Ship as `0.6.0-beta.5`.** The roadmap row named Phase 4 as `0.6.0-beta.4`. That tag is already used: `0.6.0-beta.3` is Phase 3 core (agents + hotkeys in SQLite); `0.6.0-beta.4` is agent editor polish. Phase 4 does not reopen agent work.
2. **`AIService` lives under `electron/ai/`, not `electron/AIService.ts`.** The `electron/` tree is grouped (see §2).
3. **No `ai:tool-call` in this phase.** The roadmap listed that channel. Phase 4 does not emit tool events. Phase 5 adds the channel when the tool loop lands.
4. **No model-list API.** `@ai-sdk` provider packages do not list models from the user's OpenAI / Azure / Ollama / custom host. `gateway.getAvailableModels()` lists the Vercel AI Gateway catalog, which is the wrong set. Phase 4 deletes `listModels` / “sync from provider”. Users type a model ID. Chat still uses the stored `model_id`.

## Non-goals

- No MCP, no skills, no `allowedTools`, no tool loop. Phase 5.
- No agent picker in chat. Agents still come from hotkeys + the badge.
- No change to agent / hotkey / provider SQLite schema.
- No Vercel AI Gateway as a SnapMind provider.
- No restore of Settings > Chat.
- No listing models from provider HTTP (`/v1/models`, Ollama `/api/tags`, or SDK).

## Success criteria

1. `src/services/AIService.ts` and `src/services/providers/**` are gone. Chat does not `fetch` a provider URL and does not read a decrypted key for inference.
2. `ai:send({ agentId, messages })` returns `{ streamId }` or a typed error. Main injects agent `instructions` as the system message, builds an `@ai-sdk` model from `provider.kind`, and streams.
3. Push events cover text tokens, reasoning (rendered as today's `<think>` blocks), web-search `ChatSource`s, success, abort, and failure.
4. Stop and `chat:abort` cancel the in-flight `streamText`. One stream at a time; a new send aborts the previous.
5. Reasoning, web search, images, abort, and generation params (`temperature`, `maxTokens`, `topP`) behave as they do on `0.6.0-beta.4`.
6. Settings > Models has add / edit / delete by model ID only. The sync control is gone.
7. Unpackaged runs write **debug** AI logs to the electron-log file and the main console, scoped, with `streamId`, and without secrets.
8. Vitest, lint, `tsc` ×3, and `build` pass. Old adapter tests are replaced by `electron/ai` tests.

## §1. Architecture

```
Renderer (useChatStore)
  → ipc invoke  ai:send { agentId, messages }
Main (electron/ai/AIService)
  1. Load agent + provider + model from SQLite
  2. Decrypt api_key (SafeStorage); skip key check for ollama
  3. createLanguageModel(kind, config)
  4. streamText({ model, messages, abortSignal, ...params })
  5. webContents.send  ai:token | ai:reasoning | ai:source | ai:done | ai:error
Renderer
  → append to the assistant message
  → ipc invoke  ai:abort { streamId }
```

**Who resolves.** The renderer still uses `resolveAgent` for the badge and for a fast local fail. `ai:send` always re-resolves in main. Main is the source of truth. The renderer does not send provider IDs, params, or keys.

**Messages.** The renderer sends conversation turns (`user` / `assistant` / existing `system` from the user). It does not prepend `agent.instructions`. Main prepends instructions as a system message when they are non-empty. The renderer filters `role: 'error'` before send, as today.

**Secrets.** `providers:list` may still return a key to Settings for edit (today's DTO). Chat never uses that key. Inference reads the key only in main.

### 2.1 File naming

Match the existing `electron/` convention. Do not pick one casing for every file.

| Case | When | Examples |
|---|---|---|
| **PascalCase** | The file's default export is a class (or a service whose name is the class) | `AIService.ts`, `AgentsService.ts`, `LogService.ts` |
| **camelCase** | The file exports functions or a register helper, not a class | `createLanguageModel.ts`, `mapMessages.ts`, `redact.ts`, `registerIpc.ts`, `registerAiIpc.ts`, `urlResolvers.ts` |

`electron/ipc/registerAiIpc.ts` is camelCase because it registers handlers. It is not a class.

## §3. IPC contract

`preload.ts` and `src/types/index.d.ts` stay the contract. Renderer uses `window.electronAPI`.

### 3.1 `ai:send` (invoke)

Request:

```ts
{
  agentId: number;
  messages: Message[]; // from src/types/chat.d.ts; no empty assistant placeholder
}
```

Success: `{ streamId: string }`.

Failure (no stream starts): `{ error: { code: AgentResolveErrorCode | 'no_api_key' | 'unknown_kind' | 'send_failed'; message: string } }`.

`AgentResolveErrorCode` matches today's resolver (`agent_missing`, unbound provider/model, and the same user-facing copy).

### 3.2 Push events (main → renderer)

All events include `streamId`. The renderer ignores events for a stale id.

| Channel | Payload | UI |
|---|---|---|
| `ai:token` | `{ streamId, text: string }` | Append to assistant `content` (string or text part) |
| `ai:reasoning` | `{ streamId, text: string }` | Concatenate; wrap the finished reasoning span in `<think>…</think>` so `useChatMessage` does not change |
| `ai:source` | `{ streamId, source: ChatSource }` | Append to assistant `sources` |
| `ai:done` | `{ streamId, reason: 'stop' \| 'aborted' }` | Clear loading. If `aborted` and the send was user-typed, append today's “Response is aborted.” system line. Hotkey seed send ignores abort, as today |
| `ai:error` | `{ streamId, message: string }` | `role: 'error'` (or fill the empty assistant bubble); clear loading |

### 3.3 `ai:abort` (invoke)

`{ streamId: string }` → `{ ok: true }`. Missing / already finished ids are no-ops.

Existing `chat:abort` (main → renderer) still fires. The chat store calls `ai:abort` for the current `streamId`.

### 3.4 Concurrency and lifecycle

- One in-flight stream per app. A new `ai:send` aborts the previous controller first.
- Hide window: stream keeps running (tray-resident).
- Navigate Settings ↔ Chat: stream keeps running; `useChatStore` still owns messages.
- Quit: abort all, then exit.

No `ai:list-models`. No `ai:tool-call` in this phase.

## §4. `@ai-sdk` mapping

Dependencies (exact versions pinned at implement time):

| SnapMind `kind` | Package | Factory |
|---|---|---|
| `openai` | `@ai-sdk/openai` | `createOpenAI({ apiKey, baseURL })` |
| `azure-openai` | `@ai-sdk/azure` | `createAzure({ apiKey, resourceName / baseURL, apiVersion })` |
| `anthropic` | `@ai-sdk/anthropic` | `createAnthropic({ apiKey, baseURL })` |
| `google` | `@ai-sdk/google` | `createGoogleGenerativeAI({ apiKey, baseURL })` |
| `deepseek` | `@ai-sdk/openai-compatible` | `createOpenAICompatible({ name: 'deepseek', apiKey, baseURL })` |
| `qwen` | `@ai-sdk/openai-compatible` | same, DashScope base (today's `deriveQwenApiBase`) |
| `ollama` | `ollama-ai-provider` | local host; no API key |

Also: `ai` (core `streamText`). Host / base URL derivation reuses the rules in `src/services/providers/core/urlResolvers.ts`, moved next to `createLanguageModel.ts` (or imported from a small `electron/ai/urlResolvers.ts` copy — do not leave that file in the renderer).

`streamText` always. Delete the providers' non-streaming branch with the adapters.

**Params.** `temperature`, `maxTokens`, `topP` from the agent `config_json`, with today's defaults `0.7` / `2048` / `0.95`.

**Reasoning.** When `agent.reasoning` is true, pass the provider's reasoning option (`providerOptions` / `openai.reasoningEffort` / Anthropic thinking / Google thinking, per SDK docs at implement time). Stream reasoning parts on `ai:reasoning`.

**Web search.** When `agent.webSearch` is true, attach the provider's search tool where the SDK has one (OpenAI `webSearch`, Google search, Anthropic web search). Map citations to `ChatSource`. Providers without an SDK search tool log a warning and run without search — no crash.

**Images.** `ImageContentPart` becomes an SDK image part (`data` + `mimeType`). Text-only messages stay strings.

**Abort.** `streamText({ abortSignal })` tied to the `streamId` controller.

## §5. Renderer changes

- `useChatStore` keeps `AbortController` only as a local “this send is current” guard, or drops it in favour of `streamId`. It must not call `AIService`.
- `executeStreamingRequest` becomes: `aiSend` → subscribe to `ai:*` for that `streamId`.
- Pre-send: if local `resolveAgent` fails, keep today's error message and skip IPC. If it succeeds and main still fails, show main's `error.message`.
- Delete `ProviderFactory` usage in `ModelTable` (sync). Keep manual add / edit / delete via `models:upsert` / `models:delete`.
- Chat UI (badge, markdown, thinking parse) stays.

## §6. Logging

Today `LogService` writes the **file** at `info`, so `debug` never reaches disk. Phase 4 changes that for unpackaged runs.

| Build | File | Console |
|---|---|---|
| `!app.isPackaged` | `debug` | `debug` |
| packaged | `info` | off (unchanged) |

Scopes: `ai`, `ai.send`, `ai.stream`, `ai.abort`, `ai.model`.

Every stream line includes `streamId`, `agentId`, `provider.kind`, `modelId` (never `apiKey`).

**Must log**

- send start
- resolve ok / fail + code
- model factory kind + base URL host (not full URL with query secrets)
- `streamText` start
- first-token latency (ms)
- counts: token chars, reasoning chars, source count
- done / abort / error + duration

**Token text:** `debug` only, truncated (80 characters). `info` logs counts.

**Never log:** API keys, `Authorization`, `config_json` blobs that contain secrets, raw SDK request bodies.

`electron/ai/redact.ts` is the single helper. Tests assert keys do not appear.

## §7. Models settings

Remove:

- `Provider.listModels` / `buildListModelsRequest` / `parseModelsResponse`
- Sync / refresh-from-API in `ModelTable`
- Any renderer `fetch` to a models endpoint

Keep:

- SQLite `provider_models`
- Add / edit / delete by `modelId` + display name + capabilities
- Agent editor still requires `provider_id` and `model_id` to save

- `mapMessages`: text, image parts, skip `error` roles, main injects instructions

- Chat store: no import of `AIService` / `ProviderFactory`; abort and error paths
- Drop all `src/services/providers/**` tests
